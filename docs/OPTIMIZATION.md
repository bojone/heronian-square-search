# 优化与辅助搜索记录

本页总结正式版本的性能改进、未采用的实验和辅助搜索。原始 JSON 数据在 `evidence/benchmarks/` 与 `experiments/` 中。

## 1. CPU v18

v18 将共享惰性素因子的完整 64 位 gcd 改为与 `inert_part` 的 32 位 gcd。

验证记录：

- 完整 5000 根边候选数：`151842556`；
- 第二组已知解候选数：`1194756`；
- 等价整数分支检查：`4501500` 对；
- 动态覆盖复用通过。

同负载比较：

| 区间 | v17 秒数 | v18 秒数 | 加速比 |
|---|---:|---:|---:|
| `500000–500015` | 134 | 115 | 约 1.165× |
| `1160000–1160015` | 158 | 152 | 约 1.039× |

v19 尝试在完整 gcd 前加入 3、7、11、19 的模过滤；同负载 v18 为 142 秒、v19 为 143 秒，因此没有采用。

原始数据：`evidence/benchmarks/cpu-opt-benchmark.json`。

## 2. GPU v42

v42 在 `l` 不可能提供惰性因子，或两个数都没有分裂素因子时，直接跳过 gcd。

主要特性：

- `launch_bounds(128,3)`；
- 162 个寄存器；
- 主循环无 spill store/load；
- 缓存高斯组合及低 4 位预过滤；
- 保持 128 位精确四次方检查。

同负载 v40 为 477 秒，v42 为 470 秒；另一次 v42 为 467 秒。首次正式生产检查点由 GPU3 在根边 `5547740` 处生成，状态、日志和二进制哈希均通过。

未采用或拒绝的版本：

- v37：浮点范围预过滤，同负载慢约 7.7%；
- v38：约快 1%，但未选用；
- v39：寄存器调度不占优；
- v41：分支慢约 4.1%；
- v43：惰性素数掩码，慢约 6.6%；
- v44：32 位缓存坐标范围不足，第二组已知解准备阶段即被拒绝；
- v45：结果等价但完整 128 行 A/B 测试为 207 秒，而 v42 为 174 秒，慢约 19%。

原始数据：`evidence/benchmarks/gpu-opt-benchmark.json`、`evidence/benchmarks/v45-ab.json`。

## 3. 双纤维椭圆辅助搜索

`experiments/elliptic/` 保存了以下工作：

- 两个纤维模型上的系数枚举；
- 利用 $`(n,m)\mapsto(-n,-m)`$ 的对称性减少重复；
- 使用 Legendre 符号的必要条件，过滤在有效模素数下为非二次剩余的候选；
- C++ 位掩码快速过滤及中断恢复；
- 小区间与原实现逐项一致性验证。

已验证：

- 对称性前后结果逐字节一致；
- 两组已知解均保留；
- 中小素数过滤的必要条件和一致性检查通过；
- 1000 阶完整结果一致；
- 至 200000 阶的双纤维搜索完成，最终壳层 `hits_files=[]`，无新结果。

200000 阶总结见 `experiments/elliptic/elliptic-200000-summary.json`。排除条件和未覆盖范围的完整清单见[椭圆实验说明](../experiments/elliptic/README.md)。

需要特别强调：

- 搜索只覆盖由两组已知解导出的点集及各自两个挠点陪集，没有证明 $`P,Q`$ 生成全部有理点，也没有遍历其他曲线。
- $`B=200000`$ 限制的是倍乘系数 $`n,m`$，不是三角形根边；界外组合未搜索。
- 对称约减少的是重复代表，中心区域跳过依赖前序阶段已经完成。
- 模过滤只删除有效模素数下的非二次剩余；坏约化、模点无法计算和零值不会据此删除候选。
- 有理平方命中还要经过精确参数还原、非退化性、整数面积和本原性检查。

**辅助搜索不参与最终一千万根边的完整覆盖证明。** 它用于探索构造性路线，不能替代正式穷举，也不能据此宣称其他曲线、全部有理点或更大系数范围不存在解。

## 4. 重权重专项搜索

`experiments/heavy/` 针对高斯分解表示特别多的根边，尝试用 GPU 处理 CPU 成本较高的位置。

记录包括：

- 根边 `1116389`：CPU 单线程 443 秒，已验证；
- 166 行 GPU 小批次：3131 秒，独立验证通过；
- 根边 `1447225`：GPU kernel 1468 秒，独立验证通过，但主 CPU 已先完成该位置；
- 680 行大批次：7200 秒硬截止，未形成检查点，未用于覆盖。

由于与正常 GPU worker 共享设备反而降低总吞吐，未扩大该路线。见 `experiments/heavy/heavy-benchmark.json`。

## 5. 恢复与覆盖优化

恢复机制不是性能捷径，而是完整性的必要条件：

- 非连续或不可信的状态先归档，再重新计算；
- GPU 在正常停止点完成最多 512 个位置后再接续；
- 再平衡按阶段和完成集合去重，避免重复信号；
- 覆盖审计要求连续 512 行日志链；
- 重权重 `.done` 文件逐根验证，未验证批次不计入覆盖。

原始恢复记录：`evidence/benchmarks/gpu-recovery-deployment.json`。

## 6. 性能数据的使用限制

所有秒数都受以下因素影响：

- 根边区间及整数因子结构；
- CPU/GPU 同机负载；
- 候选计数定义与过滤入口；
- 编译器、架构与驱动；
- 检查点与备份成本。

因此，不应把局部加速比直接外推到整个搜索。正式采用前必须同时验证结果一致性、已知解保留和检查点可恢复性。
